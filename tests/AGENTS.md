# 테스트 작성 지침

- 이 폴더는 루트와 해당 기능의 `src/**/AGENTS.md`에 기록된 회귀 사례를 검증한다. 문서에 적힌 사례는 구현 완료를 의미하지 않는다.
- 기존 `node:test` 방식을 우선 사용한다. 현재 TypeScript 직접 실행과 `registerHooks`를 사용하는 테스트의 Node 런타임 요구 조건을 확인하고, 실행하지 못한 테스트를 통과로 보고하지 않는다.
- 기능 추가·수정 시 먼저 기존 테스트가 새 동작과 재발 조건을 검증하는지 확인한다. 충분하면 유지하고, 부족하면 기존 사례를 확장한다. 독립된 재현 조건이나 검증 계층이 필요한 경우에만 새 테스트를 추가하며, 완료 보고에 유지·보완·신규 범위를 구분한다.
- 테스트 이름에 재현 조건과 기대 동작을 적는다. 버그 수정 전 실제 실패를 확인하고, 수정 후 통과와 기존 회귀 테스트를 확인한다. 오류 동작을 기대값으로 고정하거나 `skip`/허용 오차 확대로 숨기지 않는다.
- 난수는 시드를 고정하고 시뮬레이션 시간은 직접 진행시킨다. 여러 시드의 배치도 검사하며 실패 시 시드·좌표·설정·상태를 출력한다. 공유 설정을 변경했다면 `finally` 등으로 복원하고 병렬 테스트 간 간섭을 막는다.
- 경계 바로 안/경계/바로 밖, 0·음수·NaN·Infinity, 빈 목록·상한·공간 부족을 검증한다. 허용되는 0과 금지되는 0을 구분한다. 기획 수치를 불필요하게 고정하지 않고 단위·제약·관찰 가능한 결과를 검사한다.
- 무한 루프 위험 사례는 별도 자식 프로세스에서 실행하고 부모가 시간 제한 후 종료한다. 같은 스레드의 테스트 타임아웃만으로 동기 무한 루프가 중단된다고 가정하지 않는다.
- 단위 테스트는 실제 충돌/시야 함수를, 통합 테스트는 실제 AI·전투·이동 연결을 실행한다. 상태 이름뿐 아니라 실제 피해 또는 재추적·위치 변화와 유한 시간 내 진행을 확인한다. 예상 교차 결과는 독립된 수학 계산이나 확정된 좌표 사례를 사용한다.
- UI 모형 테스트는 이벤트·수명주기를 검사한다. 좌표·레이아웃·포인터 입력 회귀는 실제 브라우저에서 화면 좌표 클릭으로 별도 검증한다. 테스트 편의를 위한 전용 전역 객체나 디버그 UI를 제품에 추가하지 않는다.
- 성능 검사는 월드 크기·개체/장애물 수·시드·런타임·측정 환경을 기록한다. 워밍업 후 반복 측정과 연산 횟수 비교를 사용하고, 장비에 종속된 단일 시간값만으로 정상 여부를 결정하지 않는다.
- 새 테스트 파일은 `package.json`의 명시적인 `test` 실행 목록에 포함한다. 테스트 실행·빌드 명령과 결과 보고는 루트 `AGENTS.md`를 따른다.
