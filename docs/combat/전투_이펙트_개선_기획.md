# 전투 연출 개선 기획

## 문서 상태

- 목적: 공격 준비·실행·적중이 더 잘 읽히도록 애니메이션과 전투 이펙트의 역할 및 구현 범위를 합의한다.
- 범위: 기존 공격·피격·상태 표시의 시각 연출 개선. 애니메이션을 우선 검토하고, 동작만으로 부족한 정보에 이펙트를 보완한다.
- 구현 여부: 미구현. 수치와 효과별 세부 연출은 실제 화면 검토 후 조정한다.

## 목표

공격마다 다른 무기와 패턴이 있지만 현재 공격 애니메이션이 제한적이고 여러 이펙트가 비슷한 프레임·밝기·짧은 페이드에 의존해 공격 종류와 타격 시점을 놓칠 수 있다. 문제의 원인을 이펙트 부족으로 단정하지 않는다. 공격자의 준비·실행 동작, 공격 실루엣과 궤적, 적중 반응을 함께 비교해 가장 적은 연출로 공격 주체·방향·위험 시점이 읽히게 한다. 모든 연출은 시각 표현으로 제한하고 피해 판정, 공격 동작과 입력을 바꾸지 않는다.

## 확인된 현재 구성

- `src/config/effects.ts`에서 이펙트 아틀라스, 프레임, 색상, 크기, 지속 시간, 움직임 설정을 관리한다.
- `EffectSprites`가 아틀라스 이미지와 Phaser Graphics 기반 선·원을 표시한다. `EffectMotion`은 시뮬레이션 시간에 따라 나타남·확대·소멸을 계산한다.
- `ImpactRenderer`는 HP가 감소한 대상을 감지해 짧은 피격 이미지를 표시한다. 적 몸체에는 별도의 피격 점멸이 적용된다.
- `CharacterRenderer`와 `EnemyRenderer`가 무기, 폭발, 장판, 보호막, 적 공격 경고와 공격 효과를 그린다.
- `PlayerAnimation`은 방향별 이동 프레임과 정지 호흡을 제공하지만 공격 자세는 별도로 표현하지 않는다. `EnemyRenderer`는 적별 단일 프레임에 이동 흔들림·기울기와 공격 준비 중 크기 변화를 적용한다.
- 적 공격은 `windup`·`active`·`recovery` 상태와 실제 위험 영역 데이터를 가지고 있어, 공격자 동작과 바닥 예고를 같은 시점에 맞출 수 있다.
- `tests/effects-browser.html`에 연쇄 번개, 톱날, 절삭, 폭발·독 장판, 적 공격, 사망을 미리 보는 화면이 있다.
- 적 사망은 현재 몸체를 짧게 페이드 아웃한다. 피해 숫자와 적 공격의 위험 범위 표시는 각각 별도 렌더러에서 관리한다.

## 이번 계획에서 해결할 문제

- **사용자 확인:** 현재 우선 문제는 공격 종류와 타격 시점을 알아보기 어렵다는 점이다. 원인이 애니메이션인지, 이펙트인지, 둘의 타이밍인지 구현 전에 비교한다.
- **코드에서 확인:** 기본 무기는 회전 검·직선 탄환으로, 캐릭터 전용 공격은 절삭·충격파·번개·함정·장판 등으로 구분된다. 여러 표현은 같은 `pulse`, `cut`, `hit` 프레임과 원형 링을 재사용한다. 플레이어 공격 자세는 없고, 적의 공격 동작은 준비 단계의 크기 변화가 중심이다.
- **기획 방향:** 먼저 `준비 동작 → 실행 궤적 → 짧은 적중 반응`의 시간 흐름을 정한다. 공격자의 몸동작과 무기 움직임으로 전달되는 정보는 애니메이션으로 표현하고, 방향·범위·접촉 지점처럼 동작만으로 불명확한 정보에만 이펙트를 보탠다. 색상은 모양·방향·시간 신호를 대신하지 않는다.
- **적중 출처 결정:** 1차 시안에서는 현재의 공통 피격 반응을 기준으로 둔다. 비교 결과 공격 종류를 적중 지점에서도 알려야 한다고 확인된 경우에만 출처 식별 정보를 추가한다. 추가할 때는 실제 피해를 준 공격 계열, 접촉 위치, 강화 상태를 전달하고 사망 연출에 필요한 최종 적중 정보가 적 제거 전에 보존되도록 한다. 피해량·충돌 결과는 이 정보로 변경하지 않는다.
- **범위 경계:** 무기 수치, 피해 판정, 공격 주기, 이동과 적 AI는 바꾸지 않는다. 공격 입력을 잠그거나 시뮬레이션 시간과 별도로 재생되는 애니메이션은 추가하지 않는다.

## 공격별 시각 언어 제안

아래는 기존 공격 목록에 대응한 제안이며, 프레임과 최종 색상·수치는 미리보기에서 조정한다.

| 공격 계열 / 기존 사례 | 읽히게 할 모양과 움직임 | 시간 연출 및 적중 피드백 |
| --- | --- | --- |
| 회전 검·톱날: Player 기본 검, 정비공 절단기 | 원형 전체를 계속 밝히지 않고, 짧은 초승달 궤적과 회전하는 날의 앞쪽 강조로 회전 방향을 드러낸다. Player와 적은 크기·색보다 궤적 모양과 경로로 구별한다. | 회전 중 얇은 잔상을 남기고 실제 접촉 때만 날 끝에 짧은 섬광을 낸다. 강타에는 굵은 이중 궤적을 한 번 추가한다. |
| 직선 투사체: 리벳·전기 볼트·캡슐·적 탄환 | 진행 방향이 분명한 머리와 짧은 꼬리를 둔다. 리벳은 짧고 묵직한 직선, 전기는 꺾인 꼬리, 캡슐은 둥근 외곽과 점멸, 적 탄환은 뾰족한 파편형으로 실루엣을 달리한다. | 꼬리는 이동 방향 반대로 짧게 흐려진다. 적중 시 머리 모양과 연결되는 작은 파열/방전/파편 반응을 내고 즉시 정리한다. |
| 방향 절삭: 교차 절삭·적 부채꼴 베기 | 공격 방향을 따라가는 한 줄 호형 궤적을 사용한다. 교차 절삭은 서로 다른 각도의 두 줄을 순차 점등해 X형을 읽게 한다. | 궤적이 공격 방향으로 짧게 그려진 뒤 바깥 끝부터 사라진다. 접촉 위치에 작은 절삭 표식을 남긴다. |
| 전기 연쇄: 기본 방전·분기·종단 과부하 | 대상 사이를 잇는 꺾인 선이 공격의 중심이 된다. 본선과 분기선은 같은 선형을 유지하고 분기 순서로 연결 관계를 보여준다. | 첫 대상에서 다음 대상으로 순서대로 점등한다. 마지막 대상에서만 가지 모양의 짧은 방전이 퍼져 종단 과부하를 알린다. |
| 중심 충격: 접지 펄스·비상 충격파·처치 폭발 | 중심에서 바깥으로 커지는 링과 짧은 방사형 균열을 사용한다. 절삭·번개와 혼동되지 않게 선형 궤적 대신 원심 확장을 유지한다. | 중심 섬광 → 외곽 링 확장 → 얇은 바닥 잔광 순으로 짧게 진행한다. |
| 설치형 함정·연쇄 기폭 | 바닥에 고정된 작은 장치 실루엣과 장전 표시를 사용한다. 준비된 함정은 장치 위에서만 점멸하고 폭발 범위는 발동 순간에 드러낸다. | 설치 → 짧은 장전 맥동 → 중심 폭발과 충격 링 → 연결된 함정의 차례 기폭으로 읽힌다. |
| 지속 장판: 잔열·점착 흔적·중계 비콘 | 이동하지 않는 낮은 바닥 문양으로 순간 폭발·투사체와 구분한다. 잔열은 균열형, 점착 흔적은 번지는 가장자리, 중계 비콘은 전기 격자와 연결선으로 구분한다. | 활성 중에는 드문 가장자리 파동만 반복한다. 종료 시 중앙으로 수축하거나 바깥부터 흐려져 지속 효과의 종료를 알린다. |
| 유인·보호막·방어 상태 | 공격 이펙트와 구별되는 안정된 동심원/외곽막을 사용한다. 유인 범위는 중심이 비어 있는 파동, 보호막은 캐릭터 외곽선으로 표시한다. | 유인은 바깥으로 낮은 밝기의 파동을 반복한다. 보호막은 획득·피격·파괴 순간에만 선명한 짧은 반응을 낸다. |
| 적 공격 경고와 발동 | 원형·직선·부채꼴 경고를 실제 판정 경계에 맞춰 표시한다. 예고의 진행 방향과 발동 공격의 형태가 이어지도록 한다. | 예고 중에는 점진적으로 차오르는 얇은 외곽선, 발동 순간에는 경계가 짧게 강해지고 실제 공격선/충격파가 이어진다. |

각 계열의 식별성은 흑백 실루엣에서도 구분되는지 먼저 확인한다. 동시에 보이는 장식은 실제 판정 경계보다 넓어 보이지 않게 하고, 피해 숫자·캐릭터 실루엣 위를 오래 가리지 않는다.

## 애니메이션 적용 제안

| 대상 | 동작 신호 | 적용 범위와 주의점 |
| --- | --- | --- |
| Player 기본 공격 | 실제 공격 생성 시 공격 방향으로 짧게 뻗거나 무기를 휘두르고 바로 복귀한다. 공격 전에 준비 자세가 필요하면 별도 시각 신호로 먼저 시작한다. | 이동 애니메이션 위에 더하는 시각 동작으로 처리한다. 걷기 프레임, 입력, 이동 속도를 잠그지 않는다. 모든 자동 공격에 큰 자세 변화를 반복하지 않고 기본 공격은 작은 움직임으로 제한한다. 준비 동작은 공격 실행 시점과 주기를 늦추지 않는다. |
| Player 대표 기술·강화 공격 | 절삭의 방향 전환, 전기 공격의 연결 순서, 함정의 설치·장전처럼 공격별 준비와 실행을 다르게 한다. 충전·강화는 같은 공격 계열의 강조 동작으로 표현한다. | 먼저 현재 스프라이트의 위치·회전·크기 조절만으로 시안을 만든다. 새 공격 프레임이 있어야 읽히는 경우에는 필요한 아트 범위를 별도 제안한다. |
| Enemy 공격 | 기존 `windup`·`active`·`recovery` 상태에 맞춰 방향을 잡고 준비 자세를 취한 뒤, 실행 순간에 몸을 뻗거나 반동을 준다. | 예고 동작은 적 공격 경고와 같은 시뮬레이션 시간에 재생한다. 바닥 경고는 기존 판정 데이터와 일치시킨다. |
| 피격·사망 | 현재 피격 점멸·밀림·페이드에 짧은 눌림, 방향 반동 또는 붕괴를 보완한다. | 기존 피해·밀림·사망 처리의 시간과 규칙을 바꾸지 않는다. 일반 피격은 짧게 유지하고, 큰 사망 연출은 화면을 오래 가리지 않는다. |

첫 시안은 기존 스프라이트의 변형과 이미 구현된 공격 상태를 활용한다. 애니메이션만으로 공격을 구별하기 어려운 투사체·연쇄 연결·위험 범위·접촉 지점에 Phaser 도형과 기존 아틀라스 이펙트를 추가한다. 새 외부 이미지는 기본 범위에 포함하지 않는다.

Player 공격 시작 동작은 `CombatSystem`과 `CharacterCombat`이 공격을 실제 생성하는 시뮬레이션 단계의 시각 이벤트에 연결한다. 이벤트에는 공격자, 공격 계열, 방향, 강화 여부를 전달하고 `GameScene`이 해당 단계에서 애니메이션에 반영한다. 이벤트는 표시 전용이며 피해·충돌·공격 주기·입력 처리에 영향을 주지 않는다. 실제 공격 생성 전에 준비 동작을 보여줄 경우에도 준비 동작의 길이만큼 공격 실행을 지연하지 않는다.

## 연출 원칙

1. **한눈에 구분:** 공격자의 준비·실행 동작, 공격 모양과 방향을 우선 구분한다. 색상은 식별을 보조한다.
2. **행동 순서 표시:** 필요한 공격은 `준비 → 발동 → 후속 동작/잔상 정리`를 따른다. 순간 피격은 예고 없이 짧고 또렷하게 표시한다.
3. **판정과 장식 분리:** 장식 이펙트의 크기나 밝기가 실제 피해 범위로 오해되지 않게 한다. 판정 범위 표시는 실제 위험 범위와 일치시킨다.
4. **화면 가독성:** 바닥 효과는 낮은 불투명도로 표시하고 캐릭터와 피해 숫자를 가리지 않는다. 다수 적이 겹칠 때 밝기와 생성 수를 제한한다.
5. **기존 스타일 유지:** 새 외부 이미지를 추가하지 않고 현재 아틀라스와 Phaser Graphics 도형·선을 우선 사용한다.
6. **설정 분리:** 이펙트 값은 `src/config/effects.ts`, Player 애니메이션 값은 `src/config/playerArt.ts`, Enemy 공격 시점·자세 값은 해당 Enemy 설정에서 기능별로 관리하고 단위를 적는다.
7. **게임 시간 연동:** 이펙트 수명은 시뮬레이션 시간에 따른다. 레벨 선택이나 일시 정지 중에는 전투와 함께 멈춘다.

| 종류 | 표시 시점 | 연출 흐름 | 구분 기준 |

| 일반 피격 | 공격 적중 | 현재의 공통 피격 표시와 몸체 반동을 기준으로 짧게 표시한다. | 공격 애니메이션과 동시에 보여도 피해 숫자·대상을 가리지 않는다. |
| 강타·강화 공격 | 강타나 충전 상태가 실제 적용된 공격 | 기본 공격 계열의 준비·실행 동작과 궤적을 한 단계 강조한다. | 별도 공격으로 오인되지 않으며, 실제 강화 상태가 적용된 공격에만 표시한다. |
| 적 사망 | 사망 확정 | 기본은 현재의 몸체 페이드다. 출처를 강조할 필요가 확인된 경우에만 마지막 공격 계열의 짧은 잔광을 추가한다. | 경험치 드롭과 혼동되지 않으며, 출처 잔광을 적용할 때 적 제거 전에 마지막 공격 정보가 보존된다. |

1차 구현 범위는 **기본 검·탄환 → 캐릭터별 대표 공격(절삭·연쇄 방전·함정) → 단계 적 공격 경고/발동**이다. Enemy 범위는 `StageEnemySystem`이 관리하는 공격 패턴과 경고 영역으로 한정한다. 일반 적의 기본 검·탄환 공격은 이번 범위에서 제외하고, 필요성이 확인되면 별도 시안에서 검토한다. 각 항목은 애니메이션 단독안과 필요한 이펙트를 더한 안을 비교한다. 지속 장판·보호막·유인·사망 연출의 세부 변경은 후속 범위로 둔다. 공통 피격 표시와 현재 사망 페이드는 1차 구현에서도 기존 동작을 유지해 비교 기준으로 사용한다.

## 구현 단계

1. `tests/effects-browser.html`에 기본 검·탄환, 세 캐릭터 대표 공격, 적 공격 예고를 같은 배경·크기에서 비교할 장면을 추가한다. 각 시나리오를 **현재 연출 / 애니메이션만 보강 / 애니메이션과 필요한 이펙트 보강**으로 전환해 비교한다. 애니메이션의 준비·실행·복귀 동작과 이펙트의 시작·중간·종료를 볼 수 있게 한다.
2. 실제 1280×720 크기, 흑백·축소 화면, 다수 공격 중첩 장면에서 공격 방향·준비 시점·적중 여부가 가장 잘 읽히는 안을 고른다. 이펙트가 필요한 정보와 동작으로 충분한 정보를 나누고 1차 완료 기준을 확정한다.
3. `PlayerAnimation`/`PlayerController`와 `EnemyRenderer`에 선택한 준비 자세·공격 동작·복귀/반동을 적용한다. `CombatSystem`과 `CharacterCombat`에서 공격 생성 시 공격자·공격 계열·방향·강화 여부를 담은 표시 전용 이벤트를 내고 `GameScene`이 같은 시뮬레이션 단계에서 받아 애니메이션에 전달한다. Enemy 동작은 `StageEnemySystem`의 공격 상태와 경고 영역에 맞춘다. 이동과 입력은 유지하고, 애니메이션 시간은 시뮬레이션 시간에 연동한다. 기획 수치는 `playerArt.ts` 및 해당 Enemy 설정에서 관리한다.
4. 애니메이션만으로 전달되지 않는 투사체 꼬리, 연쇄 연결, 접촉 위치, 범위 경고에 한해 `CombatRenderer`, `CharacterRenderer`, `EnemyRenderer`, `EffectSprites`, `EffectMotion`을 보완한다. 재사용 표현은 색만 바꾸지 않고 실루엣·방향·시간 변화 중 필요한 차이를 둔다.
5. 비교 시안에서 적중 시 공격 출처를 계속 표시해야 한다고 확인된 경우에만 공격 시작 이벤트와 구분되는 적중 이벤트를 `CombatSystem`, `CharacterCombat`, `EnemyAttackSystem`에 연결한다. 적중 이벤트는 실제 HP 감소가 발생한 공격의 계열, 접촉 위치, 강화 여부를 전달하고, 사망 연출이 필요하면 마지막 적중 정보를 적 제거 전에 보존한다. HP·피해량·충돌 결과가 유지되는 테스트를 추가한다.
6. 효과가 겹치는 브라우저 장면으로 표시 수와 객체 생성량을 확인한다. 상한이 필요하면 최대 동시 표시 수와 초과 시 우선순위를 정해 `src/config/effects.ts`에서 관리하고, 시뮬레이션 시간 정지·Scene 재시작·1280×720 실제 게임 화면에서도 확인한다.
7. 장판·유인·보호막·사망 표현은 1차 연출과 충돌하지 않는지 별도 후속 시안에서 확인한다. 이 항목은 별도 완료 범위로 관리한다.

## 수정 대상 후보

- 설정: `src/config/effects.ts`; 필요한 경우 전투 공통값은 `src/config/combat.ts`와 역할을 분리한다.
- Player 애니메이션: `src/player/PlayerAnimation.ts`, `src/player/PlayerController.ts`, `src/config/playerArt.ts`.
- Enemy 애니메이션: `src/enemies/EnemyRenderer.ts`, 필요할 때만 `src/config/enemyRoster.ts` 또는 `src/config/enemyAttacks.ts`.
- 공통 표현: `src/combat/EffectSprites.ts`, `src/combat/EffectMotion.ts`.
- 전투 표현: `src/combat/ImpactRenderer.ts`, `src/combat/CharacterRenderer.ts`, `src/enemies/EnemyRenderer.ts`.
- 미리보기·검증: `tests/effects-browser.html`, `tests/combat.test.cjs`, `tests/character-scene.test.cjs`, 필요 시 `tests/config.test.cjs`.
- 출처 연동이 시안으로 필요하다고 확인된 경우에만 `CombatSystem`, `CharacterCombat`, `EnemyAttackSystem`을 변경한다. 전투 이벤트는 시각 정보만 전달하고 피해·충돌 구조를 불필요하게 바꾸지 않는다.

## 검증 기준

- 1차 범위에서 `npm.cmd test`와 `npm.cmd run build`가 통과하고, 기존 피해량·무적 시간·충돌 판정·공격 주기·대상 선택·사망 정리 동작이 유지된다.
- `tests/effects-browser.html`에서 현재 연출·애니메이션 보강·혼합 연출을 같은 장면으로 비교하고 공격 방향·준비 시점·적중 여부를 구분할 수 있는지 확인한다. 브라우저 검증은 자동 테스트와 별도로 기록한다.
- 플레이어의 공격 자세가 이동 입력·이동 속도를 잠그지 않는다. 공격·피격 연출과 이펙트 시간은 시뮬레이션을 멈추는 선택 화면에서 함께 멈추고, Scene 재시작 후 이전 연출 상태가 남지 않는다.
- 실제 1280×720 화면과 다수 적·공격 중첩 장면에서 플레이어, 적, 경고, 피해 숫자를 식별할 수 있다. 효과 상한을 도입하면 상한 안팎에서 중요 경고와 적중 반응이 일관되게 남는다.
- 시안은 장면별 반복 확인으로 평가한다. 각 시안에서 공격 계열, 공격 방향, 준비/발동 시점, 실제 적중 여부를 기록하고, 흑백·축소·다수 공격 중첩 장면에서도 사전에 정한 통과 기준을 충족해야 한다. 기본 제안 기준은 항목별 5회 중 4회 이상 올바르게 식별하는 것이며, 시안 비교 전에 필요하면 이 기준을 조정해 기록한다. 장식이 실제 위험 범위로 오해되지 않고 캐릭터나 피해 숫자를 가리지 않는지도 확인한다.
- 1차 대상인 회전 검·투사체·방향 절삭·연쇄 번개·설치형 함정은 흑백 또는 색을 낮춘 화면에서도 실루엣·방향·시간 흐름으로 구분된다. 지속 장판·보호막 등 후속 항목은 해당 단계에서 별도로 확인한다.
- Enemy 위험 범위 경고는 실제 판정과 맞고, 장식이 판정 범위를 과장하거나 축소하지 않는다. 애니메이션만으로도 읽히는 시점과 이펙트가 보충하는 시점을 구분한다.
- 공격 출처 이벤트를 추가한 경우에만, 같은 대상이 같은 시뮬레이션 단계에서 여러 번 적중하면 실제 HP를 감소시킨 마지막 공격의 계열·접촉 위치·강화 상태를 표시한다. 무적 또는 사망 상태로 HP가 감소하지 않은 접촉은 출처로 기록하지 않으며, 처치 적중 정보는 적 제거 전에 보존한다. 복수 적중·무적 적중·처치 적중·적 제거 뒤에도 정해진 정보가 전달되는 테스트를 확인한다. 실제 피해·충돌 규칙은 기존 테스트로 유지 여부를 확인한다.
- 브라우저에서 확인한 결과, 자동 테스트 결과, 미확인 항목을 완료 보고에서 구분한다.

## 위험 요소와 대응

- **화면 과밀:** 동일한 밀집 장면으로 먼저 가독성과 렌더링 비용을 비교한다. 제한이 필요할 때만 동시 표시 상한과 초과 시 우선순위를 정해 설정으로 관리하고, 바닥 효과는 캐릭터 위 효과보다 낮은 깊이에서 표시한다.
- **판정 오해:** 공격 경고와 장식용 충격파의 역할을 분리하고, 실제 판정 범위는 기존 공격 데이터에서 가져온다.
- **성능 저하:** 현재 렌더러의 객체 수명과 실제 재사용 범위를 먼저 확인한다. `EffectSprites`는 렌더러마다 소유되며 사용량보다 많은 이미지 객체를 `end()`에서 제거하므로, 기존 구조를 지속 재사용 풀이라고 가정하지 않는다. 밀집 장면을 기준으로 효과 수·객체 생성·프레임 비용을 확인하고, 필요한 경우에 한해 풀 또는 상한을 설계한다.
- **게임 규칙 회귀:** 애니메이션·이펙트는 시각 상태로 제한하고 전투 수치·충돌 로직을 바꾸지 않는다. 출처 이벤트를 추가해도 이미 계산된 공격 결과만 전달하며, 실제 HP 변화와 공격 규칙은 기존 테스트로 확인한다.
- **새 이미지 리소스 필요:** 현재 프로젝트 지침상 새 외부 이미지는 기본 범위에 포함하지 않는다. Phaser 도형과 기존 아틀라스로 목표 표현이 어렵다는 점이 확인되면 별도 범위로 제안한다.

## 시안에서 확정할 사항

- 현재 연출·애니메이션 단독·혼합 연출 중 공격 식별에 가장 효과적인 방식
- 강타·충전 상태를 기본 공격 동작과 구분하는 최소한의 동작·실루엣
- 비교 결과 공통 피격 반응만으로 부족한 공격 계열과 필요한 최소 출처 정보
- 색상 팔레트, 각 동작·이펙트의 지속 시간·크기·불투명도
- 밀집 장면에서 필요한 경우 효과 동시 표시 상한과 초과 시 우선순위

1차 구현 범위는 기본 검·탄환, 캐릭터 대표 공격, Enemy 공격 예고다. 장판·보호막·유인·사망 연출의 세부 변경은 후속 범위로 분리한다. 위 시각 수치와 동작 강도는 현재 코드와 실제 화면 시안으로 확정하며, 피해·충돌 등의 게임 규칙은 이 문서로 변경하지 않는다.
