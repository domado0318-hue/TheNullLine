# Review Code

구현된 코드를 검토하고 문제점과 개선 방법을 제안한다.

## 작업 절차

1. AGENTS.md와 사용자 요구사항을 확인한다.
2. 구현된 코드와 관련 파일을 확인한다.
3. 사용자 요구사항대로 기능이 구현되었는지 검토한다.
4. 버그가 발생할 수 있는 부분을 확인한다.
5. 기존 기능에 문제가 생길 가능성이 있는지 검토한다.
6. 발견한 문제와 개선 방법을 정리한다.

## 검토 결과 형식

### 종합 평가
코드의 전반적인 상태를 간단히 설명한다.

### 발견한 문제
각 문제마다 다음 정보를 제시한다.

- 문제 내용
- 실제 파일 경로
- 관련 함수나 메서드 이름
- 현재 파일에서 확인한 줄번호 또는 문제를 찾을 수 있는 짧은 코드 구간
- 문제가 발생할 수 있는 조건과 실제 동작에 미치는 영향
- 코드와 사용자 요구사항에 근거한 이유
- 중요도: 높음 / 보통 / 낮음
- 개선 제안

여러 파일이 연결된 문제는 문제를 직접 일으키는 핵심 위치와 그 동작에 연결되는 관련 위치를 구분해 적는다.

### 개선 제안
발견한 문제를 어떻게 해결하면 좋을지 설명한다.

### 최종 의견
추가 수정이 필요한지 판단한다.

## 규칙

- 코드 검토 단계에서는 코드를 수정하지 않는다.
- 실제 코드와 사용자 요구사항을 근거로 검토한다.
- 실제 파일 경로와 관련 함수·메서드 이름을 함께 제시해 사용자가 문제 위치를 찾을 수 있게 한다.
- 줄번호는 검토 중 현재 파일 내용을 확인해 위치를 검증한 경우에만 적는다. 확인할 수 없으면 줄번호를 추측하지 말고, 확인할 수 없다고 밝힌 뒤 함수·메서드 이름이나 짧은 코드 구간으로 안내한다.
- 여러 파일에 걸친 문제는 핵심 위치와 관련 위치를 구분하고, 각 위치의 역할을 설명한다.
- 확인하지 않은 문제를 사실처럼 설명하지 않는다.
- 사소한 코드 스타일보다 실제 동작에 영향을 주는 문제를 우선한다.
- 문제가 없다면 발견한 문제가 없다고 명확하게 설명하고, 문제 위치 정보를 만들지 않는다.
- 검토가 끝나면 사용자의 다음 지시를 기다린다.
